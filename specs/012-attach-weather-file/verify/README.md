# Harnesses for 012-attach-weather-file

There is no test runner and no linter in this repository. These files are the gate
instead, following `specs/011-sweep-priced-controls/verify/` and, for the engine,
`specs/006-design-space-survey/verify/`.

They are **throwaway**: run by hand from the repository root with `node`, wired into no
npm script, imported by nothing in the page. `kit.mjs` drives the staged WebAssembly
engine, so anything that runs a model needs `npm run predev` first —
`public/energyplus/`, `public/schemas/` and `public/weather/` are all gitignored and a
fresh clone has none of them.

---

## No real weather file could be obtained here

**Every EPW and every DDY these harnesses use is synthetic, generated by `fixtures.mjs`.
Nothing below was measured at a weather station.**

T004 asked for two real files and neither can be had in this environment:

- **A TMYx EPW from the station picker.** The agent network proxy refuses
  `climate.onebuilding.org` outright. A CONNECT to it returns
  `curl: (56) CONNECT tunnel failed, response 403`, and the same block applies to the
  `/onebuilding` proxy origin the page uses, which is a rewrite of that host rather than
  a second source of the data.
- **A licensed CIBSE DSY1.** CIBSE's design summer years are purchased. There is no
  fetch that produces one, and there is no version of this feature's verification that
  is entitled to one it has not bought.

So the fixtures are built instead: real station metadata lifted out of the staged TMYx
index at `public/weather/stations.json.gz`, wrapped around a dry-bulb series that is a
seasonal sinusoid, a diurnal sinusoid and seeded noise. They are structurally a weather
file — 35 well-formed fields, the eight header records in order, an engine that runs
them to completion — and physically a plausible one. They are not a measurement of any
climate, and they say so in the two fields the page letters out loud: the LOCATION
record's source reads `SYNTHETIC-fixtures.mjs-not-TMYx`, and both COMMENTS records say
what the file is and what must not be read off it.

**The list of gates this makes unanswerable is below, and those gates are recorded as
not run.** tasks.md's rule is the whole of it: a gate that could not be run is recorded
as not run, and it is never recorded as passed. Nothing in this directory should be read
as evidence that the feature works on a file somebody bought.

## The files

| File | Quickstart gate | What it holds |
| --- | --- | --- |
| `fixtures.mjs` | shared | Shared. Every weather file the gates run over, generated in memory. Two real stations, fourteen EPW variants, two DDYs, and `assertStationsMatchIndex()`, which re-reads the staged index and throws if the hardcoded metadata has drifted from it. |
| `kit.mjs` | shared | Shared. The 26.1.0 schema through `localBundle()` at the full version string, `documentFor`/`idfFor` at a desk position, `thrice` for the idempotence assertion, and the engine: `runOnce` (one run, in this process, refused a second time) and `runIdf` (one run per spawned process, call it as often as you like). Also `harness()`, whose `notRun(label, why)` is how a gate that could not be answered is recorded. |
| `schema-fields.mjs` | 2 | `latitude`, `longitude`, `time_zone` and `elevation` resolved against the 26.1.0 schema, each asserted numeric, before anything writes `Site:Location` from an EPW. |

Nothing is checked in. A generated year is about 1.6 MB, which is why `.gitignore` now
ignores a `fixtures/` directory under any feature's verify folder — but the intended use
is a string in memory. `dailyMeans`, `readLocation`, `fingerprint` and the engine all
take one.

## The fixtures

Each is its own exported builder, so a harness names the file it is asserting over
rather than passing a bag of options at the call site. Every one is deterministic to the
byte: the noise is a hash of the date, the hour and the field being written, never a
running generator state. Two calls a week apart produce identical text — which gate 4
needs outright — and a day reads the same in every fixture that carries it, so the June
of `epwPartYear()` is character for character the June of `epwWholeYear()`.

| Builder | The file | Gate it serves |
| --- | --- | --- |
| `epwWholeYear()` | 8,760 records, CRLF, trailing newline; 1,612,172 bytes | 3, 5 |
| `epwCrlf()` / `epwLf()` | the same year, the two line endings | 4 |
| `epwTrailingNewline()` / `epwNoTrailingNewline()` | the same year, with and without | 4 |
| `epwLeapYear()` | 8,784 records carrying 29 February | 3 |
| `epwTwoDataPeriods()` | `DATA PERIODS,2,…` — not one unbroken year | 3 |
| `epwMissingAprilRecord()` | the 13:00 record of 15 April deleted | 3 |
| `epwPartYear()` | 1 June to 31 August | 3, 7 |
| `epwSubHourly()` | four records an hour, 1–7 January | 3 |
| `epwNoLocation()` | no LOCATION record at all | 3 |
| `epwBlankLocation()` | empty fields and onebuilding's bare hyphens, both in one record | 3 |
| `epwDaylightSaving()` | declares a DST rule and two holidays | 7 |
| `epwNoDaylightSaving()` | declares none, as every TMYx does | 7 |
| `ddyValid(schema)` | a DDY carrying the annual heating and cooling pair `designConditionsFrom` looks for | 5 |
| `ddyOtherCity(schema)` | the same, for the other station: a perfectly good DDY describing somewhere else | 5 |

Every builder takes a station, `STATIONS.london` (London-Luton.AP, 036733, GBR/ENG) by
default or `STATIONS.denver` (Denver.Intl.AP, 725650). Both rows are the index's own
`TMYx.2009-2023` entries, copied field for field and re-checked against the index by
`assertStationsMatchIndex()`.

Mid-April is not an arbitrary place to delete a record. It is inside the seed week of
TM52 equation 2.3, so a file losing that day quietly would take the comfort line's whole
season with it — which is the reason `dailyMeans` refuses rather than returning 364
means.

The sub-hourly file is a week, not a year: 35,040 records are about 6 MB and nothing
they would prove is not proved by seven days. `periodCovered` reads both the
records-per-hour and the extent; `dailyMeans` refuses this file for being a part year,
which is a different sentence and a different gate.

## What was confirmed while building these

Run against the real modules, not a copy of them.

- The good fixtures parse. `dailyMeans(epwWholeYear())` returns 365 means at an annual
  mean of 10.30 °C; CRLF and LF give identical series; a file with no trailing newline,
  a file with no LOCATION record and a file with a blank one all read their 365 days.
- Each bad fixture throws the sentence its gate needs, in `epw.js`'s own words:
  `epwLeapYear()` → *"this weather file carries 29 February, so it is a leap year of
  8,784 records…"*; `epwTwoDataPeriods()` → *"this weather file declares "2" data
  periods, and a daily mean series wants one unbroken year"*; `epwMissingAprilRecord()`
  → *"this weather file carries 23 of the 24 records 15 April needs, so no mean can be
  taken for that day"*.
- `parseEpwCalendar` reads `{ holidays: [], daylight: null }` off the TMYx-shaped file
  and both a rule and two named days off `epwDaylightSaving()`.
- **One real EnergyPlus run, through `kit.mjs`.** The default desk sized on
  `ddyValid(schema)` and run annually against `epwWholeYear()`: exit 0, 0 severe, no
  fatal, 106,824 ESO lines, 2.77 s of engine time. The `.err` reads

  ```
  ** Warning ** The following Report Variables were requested but not generated -- check.rdd file
  ************* EnergyPlus Completed Successfully-- 0 Warning; 0 Severe Errors; Elapsed Time=00hr 00min  2.77sec
  ```

  That is one run's stamp; the elapsed time moves a couple of tenths between runs and
  the counts do not. A desk with Air, Gains and System patched in runs the same year
  clean too — 0 severe, 88 lines of `.mtr`. That one warning is **not** the weather file: the same desk run on
  its design days with no `-w` at all raises it, so it belongs to the reporting set, and
  chasing it down to the variable is gate 5's job, not the kit's.
- `applyModel` three times over the attached-DDY desk is byte-identical, 22,017 bytes.
- The one-run latch works. A second `runOnce` in the same process is refused with its
  sentence rather than silently handing back the first run's ESO; three consecutive
  `runIdf` calls each return their own 608-line ESO in about 1.0 s.
- `assertStationsMatchIndex()` passes against the staged index.

Sizes and timings of the generated year, for whoever needs a working figure: 1,612,172
bytes raw, 223,503 gzipped at level 9 (13.9 %), 298,004 characters base64 of the gzip,
`dailyMeans` 6.57 ms best of 40 under Node 22, the file itself built in 34 ms. **Read
none of that as gate 1.** Research assumed 22.3 % over a different synthetic file and
this one compresses to 13.9 %, which is the point: the compression of invented data is a
property of how it was invented. A bought file's ratio is a measurement and nobody here
has taken it.

## Running them

```bash
npm install && npm run predev        # stages the engine, the schemas and the index

node specs/012-attach-weather-file/verify/schema-fields.mjs
```

`fixtures.mjs` and `kit.mjs` are imported, not run. A harness of your own starts:

```js
import { loadSchema, idfFor, runIdf, harness } from './kit.mjs';
import { epwWholeYear, ddyValid } from './fixtures.mjs';
```

`runIdf` spawns a process per run and may be called in a loop. `runOnce` runs in the
calling process and refuses a second call: EnergyPlus's `main` is not re-entrant, and
the second call throws a bare number *before doing any work*, leaving the first run's
output in `/output` for an unwary harness to read back as agreement. That measurement is
feature 006's, repeated at the head of `kit.mjs` because it is the reason the file is
shaped the way it is.

### Gate 8, driven

The page was driven in headless Chromium against the synthetic fixtures. What
was exercised and passed:

- attach, with and without a DDY beside the file; title block, site line and
  degree days all off the file's own records;
- 8,760 hours solved locally against the attached file, 0 page errors;
- no DDY beside it → no design days, no datum lines, and the sentence saying so;
- a link minted on a file desk, opened in a browser that has never seen the
  file: the desk loads whole, nothing is solved, the title block reads an em
  dash rather than a city, and the wanted file is named in its own words;
- the wrong file refused with both descriptions printed; the right one attaches
  and solves;
- reload on the link re-attaches from `localStorage` with no filesystem trip;
  the bare address comes back with **no** climate and the file merely offered,
  which is the Principle II rule this feature turns on;
- four refusals provoked deliberately — a PDF, a leap-year file, a part-year
  file, a file with one record missing — each naming what was missing;
- 390 px with a coarse pointer: the attach control, its note and the kept line
  all in view with real dimensions, both controls taking a tab stop, no sideways
  scroll;
- the units toggle with a file attached: the elevation re-letters 525 ft → 160 m,
  the degree days stay on their Celsius bases, the fingerprint in the link does
  not move and no run starts.

What was **not** run under gate 8: attaching while a study and a survey are both
in flight, and the background-tab paint check. Both need a driven study, which
is minutes of engine time per sample.

### Still not runnable here

Re-confirmed during implementation: `curl https://climate.onebuilding.org/` →
`curl: (56) CONNECT tunnel failed, response 403`.

1. **Gate 1 entirely.** Every size and timing figure in `research.md` and
   `docs/design-notes.md` is over a synthetic file. Two synthetic files already
   disagree with each other by a lot — 22.3 % and 13.9 % compression — which is
   itself the argument that a synthetic ratio settles nothing. The remembering
   budget in `weather.js` rests on this and must be re-measured on a bought file.
2. **Every reading over a licensed CIBSE DSY1**, which is the feature's actual
   subject.
3. **SC-003**, the identity check between a hand-attached TMYx file and the same
   station picked from the list. It cannot be approximated: a synthetic file has
   no station in the list to be identical to.
4. **The idfkit MCP model checks** — `load_model`, `validate_model`,
   `check_model_integrity`. No local EnergyPlus and no MCP tools here; the WASM
   runner stands in for `run_simulation` alone.
5. **The fingerprint in a browser against the fingerprint under Node.**

### T021, the station path, stated precisely

The refactor this feature starts with — `choose()` split so that a station and a
file share one `attachClimate` — is the change with the most reach and the least
direct coverage here, so what was and was not exercised is worth being exact
about.

**Exercised, in a browser:**

- the picker's search, grouping and flavour list, which work entirely offline
  because the station index is staged into `public/weather/`;
- the station **refusal** path, which is reached for real: the archive fetch
  fails at the proxy and the sheet letters *"Denver Intl AP could not be
  fetched: …"*, leaving the desk's climate untouched, with no page error;
- `attachClimate` itself, in full, on every file attach — it is one function and
  the file path is the same eight steps;
- `sourceFromStation`, in a Node harness over a synthetic archive;
- `setDesignConditions`, unchanged in behaviour and asserted byte-identical.

**Not exercised:** the dozen lines between a successful archive download and
`attachClimate` — the fetch landing, `designConditionsFrom` over a real DDY from
onebuilding, and `sourceFromStation` being handed it. Reaching them needs
climate.onebuilding.org, which this environment denies. A maintainer with
network should pick three stations and confirm the IDF each writes is
byte-identical to what `main` writes for the same desk, which is what T021 asks
for.
